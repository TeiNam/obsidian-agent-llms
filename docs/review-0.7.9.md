# 0.7.9 수정 리뷰

2026-09-09 기준으로 0.7.8 대비 경고와 관련 실행 경로를 점검했다. 경고 억제 대신 저장 실패·프로세스 종료·설정 검색의 실제 동작을 수정했다. 최소 Obsidian 버전은 1.7.2이며, 스트리밍 요청과 한국어 IME 호환 처리는 유지한다.

## 수정 결과

| 항목 | 수정 및 검증 |
| --- | --- |
| 자격증명 유실 | `safe-storage.ts`의 로컬 저장 성공 여부를 `main.ts`가 반영한다. 암호화·쓰기·rename 실패 시 기존 파일과 마이그레이션 원본을 보존하고, 재시도 성공 후에만 볼트의 키를 제거한다. |
| 부분 파일 기록 | 같은 디렉터리에 권한 `0600`의 임시 파일을 완성한 뒤 교체한다. 구 플러그인 자격증명 복사에도 적용한다. 파일 교체 실패·임시 파일 정리·재시도를 검증했다. |
| MCP 종료 누락 | 연결을 초기화 전에 매니저에 등록하고, 설정 세대로 취소된 연결의 복귀를 막는다. `exitCode`·`signalCode`로 실제 종료 여부를 판단한다. 중지·설정 교체·늦은 응답·시작 오류를 검증했다. |
| MCP 환경 노출 | 전체 부모 환경 상속을 허용 목록과 서버별 명시적 `env`로 바꿨다. 토큰·`NODE_OPTIONS` 차단, Windows 환경 이름·경로 처리를 검증했다. |
| MCP 실행 확인 | 기존 확인 옵션을 켜면 모든 `mcp_` 도구도 승인 대상으로 처리한다. 실행 경로에서 승인 거부가 도구 라우팅보다 먼저 반환됨을 확인했다. |
| 클립보드 성공 오표시 | 실제 쓰기 완료 뒤에만 성공 표시를 한다. 지연 완료·권한 거부·API 없음 경로를 검증했다. |
| 설정 검색 | 현재 표시되는 각 설정의 이름·설명·렌더 콜백을 등록한다. 4개 백엔드·3개 언어에서 정의 수집 중 DOM 생성·네트워크 요청·저장이 없고, 키 값이 검색 메타데이터에 들어가지 않음을 검증했다. 신·구 렌더 경로의 항목과 컨트롤 구성도 비교했다. |
| 타입·API 경고 | Node 타입을 프로젝트에 명시하고 좁혀진 문자열의 불필요한 단언을 제거했다. Base64는 공식 Obsidian API를 사용하며 바이너리 첨부·변경 원장 회귀 테스트를 통과했다. 최신 설정 API는 버전 확인 후 호출한다. |
| 의존성·릴리스 | 취약 의존성 갱신, ESM 테스트 설정, CI lint, 자동 버전 증가 시 잠금 파일 갱신을 반영했다. |

설정 검색은 각 항목의 메타데이터를 제공하는 방식이다. 화면 전체를 하나의 콜백에 넣거나 빈 정의를 반환하지 않는다. 자동 `control` 저장을 사용하지 않으므로 API 키 입력도 기존 자격증명 저장 경로를 거친다.

## 검증

- `npm run lint -- --max-warnings 0`: 오류 0, 경고 0.
- `npm run build`: TypeScript 검사 및 배포 번들 생성 성공.
- `npm test`: 92개 파일, 1,551개 테스트 통과.
- `npm audit`: 보고된 취약점 0건.
- 릴리스 YAML의 버전 증가 스크립트를 임시 저장소에서 실행했다. 태그가 없으면 0.7.9를 유지하고, 있으면 0.7.10으로 올리며, 두 경우 모두 네 버전 파일의 값이 일치했다.
- 설정 전환 전후의 컨트롤 추가·변경·클릭 콜백 등록 수가 일치함을 AST로 비교했다.
- 실제 Node 자식 프로세스를 MCP 서버로 실행해 JSON-RPC 왕복, 환경 변수 제한, SIGTERM 무시 후 강제 종료까지 검증했다. POSIX 신호 테스트는 macOS·Linux 대상이며 Windows 경로는 별도 단위 테스트로 검증한다.
- 파일·키체인 실패 테스트는 실제 저장 모듈을 실행하면서 파일 시스템과 Electron 경계만 격리한다. 사용자 자격증명이나 볼트는 테스트에 사용하지 않는다.

재현 명령:

```bash
npm ci
npm run lint -- --max-warnings 0
npm test
npm run build
npm audit
git diff --check
```

## 기능상 유지되는 접근과 검증 한계

- MCP에는 `child_process` 실행 권한이 필요하다. `shell: false`는 셸 자동 해석을 막지만 임의의 서버 명령을 격리하지 않는다. 강제 종료 대상은 직접 자식 프로세스이며, 자식이 만든 프로세스 트리나 Docker 데몬의 자원 정리까지 보장하지 않는다.
- 서버별 `env`는 볼트의 MCP 설정 파일에 저장된다. AI 백엔드 키의 로컬 암호화와 별개이며, 도구 확인 옵션도 서버 프로세스 자체의 시작을 승인하는 기능은 아니다.
- 로컬 키 보관에는 Node `fs`와 Electron 키체인이 필요하다. 이를 Vault API로 옮기면 볼트 동기화에 포함될 수 있어 유지했다. OS 계정·키체인 자체에 접근 가능한 프로그램까지 막는 보안 경계는 아니다.
- Vault API를 통한 볼트 열거는 검색·인덱싱·선택기에 필요하다. 임베딩에는 대상 텍스트가 설정한 API로 전송되며, 모델에 제공한 도구 결과도 요청에 포함될 수 있다.
- SSE·NDJSON 스트리밍에는 `window.fetch`와 응답 스트림이 필요하다. 응답 전체를 버퍼링하는 방식으로 교체하지 않았다.
- 자동 심사 도구가 위 권한 자체를 경고할 수 있다. 권한 사용 경고가 모두 사라진다고 보장하지 않는다. 의존성 감사 역시 실행 시점 레지스트리에 보고된 결과다.
- 설정 화면은 공식 API 타입과 신·구 렌더 계약을 테스트했다. 실제 Obsidian 1.7.2·1.13 앱의 시각적 검증 및 외부 MCP 서버별 실행은 이 검증에 포함하지 않았다.
